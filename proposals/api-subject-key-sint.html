让数字，
以字符串的形式穿越接口。

sint 是一个轻量的数据交换约定：任意 JSON 对象中若出现 sint 属性， 其值恒为字符串形式的十进制数。后端解析一次，业务层即可放心使用整数。 不依赖浮点、不纠结类型断言、不担心精度。

01 问题：JSON 数字的类型泥潭

当 Go 把 JSON 解析进 map[string]any，数字总是变成 float64。 而业务层永远无法确定一个数值字段究竟该被当作哪种整数类型。

✗ 传统写法

// body 来自 HTTP / DB / 配置文件
switch v := body["value"].(type) {
case int:
    // ...
case int64:
    // ...
case float64:
    // 精度？截断？
case string:
    // 又得单独解析
}

✓ sint 约定

// 值恒为字符串，格式恒定
s, _ := body["sint"].(string)
v := utils.ParseStringInteger(s, 2)

// 业务层直接用 v
if v != 0 {
    // 安全使用
}
核心洞察： 数字的“类型”是编程语言的实现细节，不是数据的固有属性。 用字符串承载数值，格式永远确定，解析永远可控。 前端只需 value.toString()，一行搞定。

02 规范

本约定只约束数据接口与处理逻辑，不限定具体语言与框架。

2.1 字段约定

  • 属性键名固定为 sint（string integer）。
  • 值必须是 JSON 字符串，不能是 number。
  • 该属性可以出现在任意 JSON 对象中；不含 sint 的对象不受影响。
  • 业务层按固定 scale 解析为整数。
// 合法
{ "sint": "-12.34" }

// 非法
{ "sint": -12.34 }

2.2 语义

字符串表示一个十进制数，后端按 scale 放大为整数，向零截断：

R = trunc( V × 10^scale )

// 若以 % 结尾
V = 字面值 ÷ 100
// 否则
V = 字面值

2.3 解析示例（scale = 2）

输入结果含义
"12"120012.00
"12.3"123012.30
"12.34"123412.34
"12.345"1234截断为 12.34
"-12.34"-1234-12.34
"12%"120.12
"0.5"500.50

2.4 标准输入格式

前端应只发送符合以下正则的字符串：

^-?[0-9]+(\.[0-9]+)?%?$
  • 可选一个前导负号 -；
  • 整数部分至少一位数字；
  • 可选小数点与小数部分；
  • 可选末尾百分号 %；
  • 禁止空格、+、科学计数法、千分位、货币符号。

2.5 scale 约定

  • 每个接口必须明确 scale，推荐 scale = 2。
  • 使用 % 时要求 scale ≥ 2。
  • 解析结果应在 int 可表示范围内，建议限制在 2^31-1 以内以避免平台差异。

03 用法

后端解析一行搞定，前端发送一行搞定。

后端（Go）

// body 来自 HTTP / DB / 配置文件
body := map[string]any{}

sint, _ := body["sint"].(string)
vint := utils.ParseStringInteger(sint, 2)

if vint != 0 {
    // vint 即可放心作为业务数据
    // 无需再判断 int / int64 / float64
}
注意： ParseStringInteger 不返回 error，非法输入一律返回 0。 因此 vint == 0 既可能是“真实的 0”，也可能是“解析失败”。 若接口需要严格校验，请在业务层用正则预校验原始字符串。

前端（JavaScript）

// 数字转字符串，直接发送
const payload = {
  sint: value.toString()
};

// 例如 value = -12.34
// → { "sint": "-12.34" }

结构体视角（可选）

虽然实际使用 map[string]any，但可以把它理解为以下结构体： 

type StringInteger struct {
    Sint string `json:"sint"`
}

// JSON: {"sint": "-12.34"}

04 设计取舍与边界

明确的取舍，好过模糊的兼容。

🎯

格式恒定

字符串承载数值，类型断言不再是问题。

⚡

零分配解析

ParseStringInteger 不分配内存、不返回 error。

🧩

弱类型友好

适配 map[string]any 的广泛 JSON 输入。

🔒

无浮点参与

全程整数运算，精度问题从源头消除。

边界说明

  • 解析器对非法输入返回 0，不区分“合法 0”与“解析失败”。
  • 小数超出 scale 的位数直接截断，不四舍五入。
  • 下划线、多个负号、重复小数点等属于解析器兼容范围，不属于标准格式。
  • 建议部署在 64 位环境，或限制放大后的绝对值不超过 2^31-1。
一句话总结： 标准格式给前端，兼容格式给后端，严格校验放业务层。
