Open Proposal · Dev Workflow

把正在开发的功能，
从宿主里抽出来

一种让「改逻辑」和「重启程序」彻底解耦的开发方式。 让尚不稳定的功能脱离宿主，独立构建、独立执行、随时替换—— 而整个客户端或服务的现场，全程不动。

问题

在今天的客户端与后端架构里，功能逻辑的变更是高频的，而验证一次变更的代价往往高得不成比例。 你改了一行判断、调了一个参数，接下来要面对的却是：重新构建整个客户端、或者重启整个服务进程、 等它重新加载、重新登录、重新把界面点到刚才那个状态——然后才有机会看到那一行改动是否生效。

真正变化的，往往只是少数几个还在开发中的功能。 其余成百上千行代码是稳定的、不需要跟着动的。 让整条构建与启动链路为这几个功能陪跑，是一种沉默而持续的浪费。 更糟的是它对心流的破坏：每次想验证一个小改动，都要先付出一次「重启税」。

核心思想

默认路径
  • 改动落在宿主程序内部
  • 验证一次 = 重新构建 / 重启一次
  • 迭代周期被构建时间绑架
  • 调试入口与正式入口纠缠不清
抽离路径
  • 开发中的功能挂载到一条独立命令上
  • 验证一次 = 重新编译这一条命令
  • 宿主进程始终不动，随时可被调用
  • 调试路径与正式路径并行、互不干扰
与其让整个程序重启来加载新逻辑，
不如把新逻辑切出去，让它自己去构建、自己去运行。

具体做法是：在本地维护一条命令，内部持有一张功能注册表。 把正在开发的功能挂载上去，各赋予一个标识；调用时按约定传入标识、子命令和参数， 就能触发其中任意一个功能的最新版本。 前端则通过一个薄代理接入——它接收请求、转交命令执行、再把结果原样回吐。 改动逻辑后，只需重新编译这一条命令，几秒钟完成，下一次调用就是新版。

关键洞察

本质

把局部逻辑抽出来单独构建、单独执行—— 本质上就是组件级测试。

唯一的区别在于：它套上了最终的 UI 界面去触发调用。 不是写一个脱离真实的单元测试，也不是用 mock 假装环境， 而是让真实的前端、真实的参数、真实的交互，直接打到那块还在打磨的逻辑上。

这个视角一旦成立，很多事就顺了：抽离不是「为了调试而搭的临时脚手架」， 它是组件级测试的一种自然形态——只不过组件跑在真实调用链里， 由真实的界面驱动，验证的是真实的行为，而不是模拟出来的行为。 调试与测试在这里不再是两件事。

适用场景

🖥️

Web 技术构建的客户端

界面逻辑本身就是可插拔、可热加载的。 在这种架构里，把底层的功能逻辑抽成独立命令尤其自然—— 界面层不必重建，底层功能可以独立迭代。

客户端窗口、会话状态、用户操作现场全程保留， 开发者能在真实的使用场景里反复验证一块正在开发的功能。

🌐

前后端分离的服务

前端天然与后端分离，本就通过不同的接口来调用后端能力。 在这种结构下，把开发中的接口逻辑抽成独立命令，前端几乎无感。

真实接口与调试接口并行存在，调用点写法一致， 切换只在一处开关——业务代码不必为调试而分叉。

工作流

把功能挂载到命令上
将要调试的功能逻辑写进命令源码，注册到功能表里，赋予一个标识。
按约定调用
传入三个要素：触发哪个功能、执行什么子命令、以及一段结构化参数。
重新编译这一条命令
逻辑改完，只需重新编译这一个命令，几秒完成，宿主进程完全不受影响。
立即验证
下一次调用自动拿到新版本，无需重启任何长驻进程，迭代闭环极短。

它带来什么

⚡
迭代周期骤减
验证成本从「构建整个客户端」降到「编译一条命令」，几乎可以忽略。
🧩
关注点分离
不稳定的逻辑被隔离在独立容器里，不会污染宿主程序的稳定部分。
🔁
宿主零打扰
长驻进程、窗口、会话状态全程不动，调试不打断任何现场。
🧪
真实 UI 驱动的组件测试
不是 mock，也不是脱离环境的单测——真实界面、真实参数、真实行为。
🎛️
按需触发
一张功能表 + 统一参数约定，想调哪个功能就调哪个，边界清晰。
🪶
前端无感切换
真假两条调用路径响应形状对齐，业务代码不必为调试单独写一套。

它不是万能的

不替代正式链路的最终验证。 调试路径跑通，不等于上线就绪。抽离出来的功能是独立副本， 与正式实现之间存在分叉的可能，需要明确「调试通过后如何回填」的约定。
本质是一个「任意功能调用入口」。 它只应存在于本地开发环境，绝不应面向生产开放。 调试代理必须在非开发环境下直接拒绝服务。
与热重载不是同一件事。 热重载解决的是「改代码后进程内自动重载」； 这套思路解决的是「把不稳定功能从宿主中切出去」。 两者可以并存，但边界要清楚，否则行为容易不一致。

一句话

把编译期问题转化为运行期调用。

传统上，「逻辑变更」和「程序启动」是绑定的：改了逻辑就得重新启动。 而这套思路把两者解耦——逻辑放在一个可以随时重新生成的独立单元里， 程序在运行期通过一次调用来获取它的最新形态。 它不宏大，也不复杂，但它把开发者从反复重启的循环里解放了出来。
