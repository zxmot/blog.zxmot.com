作坊式开发的全生命周期
不是瀑布，是一连串不能塌的关键节点

设计、开发、上线、推广——这些标志性阶段大家都知道，但决定生死的往往不是这些大词，而是夹在它们中间的那些细节。

细节做到位，四两拨千斤；没做到位，一路滑向死胡同。

大家都知道的那四个阶段

设计 开发 上线测试 推广及商业化

这四个词本身没有错，但它们太粗了。

真正决定项目生死的是夹在它们之间的关键节点：你封存了原始动机吗？你验证过问题吗？你写下了不做清单吗？你敢收费吗？你设了退出条件吗？

这些节点没做好，四个阶段做得再漂亮，也只是一条通往死胡同的路。

00

封存原始动机

动手前把「为什么」钉死，之后不许偷偷改

关键点

用一段话，原封不动写下：日期、你观察到的场景、谁在痛、现在怎么解决、你打算怎么做、成功信号、失败信号、你愿意投入多少、什么情况下你会放弃。写完封存，只在重大决策前回看。

✓ 做到位 → 四两拨千斤

  • 面对质疑时，你有一句话能钉住自己：我不是为了做产品，我是为了解决这个场景。
  • 功能取舍有了锚点，不被用户、资本、朋友圈牵着走。
  • 项目就算失败，你也清楚死在哪个假设上，而不是一笔糊涂账。
  • 动机纯粹，做久了不会疲惫、不会迷茫。

✕ 没做到 → 后果严重

  • 动机被悄悄替换成「技术爽感」——为了开发而开发。
  • 做了一堆功能，最初那个痛点早就丢了，最后自己也说不清为什么做它。
  • 投资人说不性感就转型，用户说加个功能就加，产品变成大杂烩。
  • 项目没有灵魂，做久了只剩疲惫。
☠ 典型死法：为了开发而开发
动手

写 why.md，存档，只在重大决策前回看。不要每天看，会被自己感动。

01

问题验证

问过去行为，不问「你觉得怎么样」

关键点

找 5–20 个目标用户，聊他们现在怎么解决这个问题，为此花过多少钱、多少时间。不要问「你会用吗」，要问「你上次遇到这个问题是什么时候，你当时做了什么」。

✓ 做到位 → 四两拨千斤

  • 你手里有一批真实用户愿意留邮箱、预约、甚至直接付费。
  • 你知道用户现在的替代方案是什么，你的切入点在哪。
  • MVP 的每一步都有依据，开发时心里有底。
  • 后面融资、推广、定价，你都有真实素材可以讲。

✕ 没做到 → 后果严重

  • 只问朋友「你会用吗」，收获 100 个「牛逼」，然后没人用。
  • 做了一个没人疼的问题，自己感动自己。
  • 开发到一半才发现方向错了，时间和热情一起烧光。
  • 没有用户原话，后面所有决策只能靠猜。
☠ 典型死法：自嗨
动手

做 5 个访谈，只记录原话，不记录评价。问「上次」「花了多少」「后来怎么解决的」。

02

赌注与边界

一页纸，最重要的是「不做清单」

关键点

写一页纸：用户、痛点、承诺、核心功能、不做清单、成功标准、时间盒。不做清单比做清单更重要——它决定了你不会被什么带走。

✓ 做到位 → 四两拨千斤

  • 开发时不被「顺便也做」带偏。
  • 新想法来了，有判断标准，不会被牵着走。
  • 时间盒到点，能冷静判断：继续、缩小、转型、关停。
  • 团队或合作者一看就懂，不用反复解释。

✕ 没做到 → 后果严重

  • 功能膨胀，永远做不完，永远差一点。
  • 没有成功标准，做完了也不知道算不算成功。
  • 「再打磨一下」变成无限期拖延。
  • 别人问「你到底要做什么」，你答不上来。
☠ 典型死法：功能膨胀 + 无限打磨
动手

写 one-pager.md，不超过一页。不做清单至少写 5 条。

03

手工 / 原型闭环

能手工先手工，能预售先预售

关键点

用 Figma、Notion、表单 + 邮件、人工服务，先把核心流程跑通，让用户提前参与。不要一上来就写通用系统。

✓ 做到位 → 四两拨千斤

  • 几天就知道核心流程有没有价值，而不是几周。
  • 用户提前成为共创者，反馈真实且及时。
  • 试错成本极低，可以大胆改方向。
  • 预售拿到的钱，直接变成开发动力。

✕ 没做到 → 后果严重

  • 一上来就写通用系统，三个月后才发现方向不对。
  • 追求完美 UI，迟迟不给人用，热情在等待中耗尽。
  • 用户第一次看到的是半成品，反馈全是表面问题，听不到真需求。
  • 代码写了一大堆，没人用过，全是沉没成本。
☠ 典型死法：技术先行，用户缺席
动手

用最低成本的方式跑通一次核心流程，哪怕全是人工。目标是「让人用上」，不是「让人看到代码」。

04

MVP

只做一个端到端闭环，其他全砍

关键点

输入 → 核心动作 → 输出 → 反馈 / 付费。一个闭环跑通，比十个半成品功能有价值。陌生人能独立完成核心任务，才算过关。

✓ 做到位 → 四两拨千斤

  • 陌生人能独立完成核心任务，不用你在旁边解释。
  • 有明确的东西可以给别人看、给别人用。
  • 为下一步的反馈和收费打好基础。
  • 你能清楚说出「这个产品解决了什么」，一句话。

✕ 没做到 → 后果严重

  • 加了一堆「顺便也做」，核心闭环没跑通。
  • 用户拿到手不知道怎么用，你还得在旁边解释。
  • 自己觉得很好，但没人能独立用起来。
  • 功能很多，但没有一个能收费。
☠ 典型死法：功能堆砌，闭环缺失
动手

画一条线：输入 → 核心动作 → 输出 → 反馈/付费。问自己「这条线能自己跑完吗」。不能，就砍功能。

05

朋友碰撞 / 种子反馈

朋友给情绪和盲点，用户给行为和钱

关键点

分三类人：目标用户、同行、潜在付费者。记录原话，不记录评价。问「你会怎么用 / 为什么不用」，不问「你觉得怎么样」。

✓ 做到位 → 四两拨千斤

  • 拿到真实盲点和第一批种子用户。
  • 创作欲被激发，但情绪和需求分得清。
  • 假设变成可以验证的实验，而不是空想。
  • 朋友成为传播节点，而不是只会说「牛逼」的啦啦队。

✕ 没做到 → 后果严重

  • 把「朋友说好」当成市场验证，继续闷头开发。
  • 被「你应该加个 XX 功能」牵着走，产品变成大杂烩。
  • 情绪被打击或捧上天，失去判断。
  • 朋友碍于情面不说真话，你活在幻觉里。
☠ 典型死法：把鼓励当需求
动手

建 feedback.md，只记原话。朋友说「挺好的」，追问「你会用它替代现在的什么工具」。

06

私测 / 预售

免费测听不到真话

关键点

拉 10–50 个真实用户，收费，观察留存。愿意付费比愿意点赞重要一百倍。定价可以低，但必须收。

✓ 做到位 → 四两拨千斤

  • 有付费用户，有人续费、有人推荐。
  • 有留存数据，知道谁在用、为什么用、什么时候不用。
  • 有真实的现金流信号，能判断这条路能不能走。
  • 面对质疑时，你能说「已经有人付钱了」。

✕ 没做到 → 后果严重

  • 免费给一堆人用，收到一堆「挺好用」，然后没人回来。
  • 靠朋友撑场面，数据好看但不可持续。
  • 不知道用户为什么来、为什么走，只能靠猜。
  • 上线后才想定价，手忙脚乱，得罪早期用户。
☠ 典型死法：免费测试 + 虚假繁荣
动手

设一个价格，找 10 个人收钱。哪怕只收 1 块钱，也比免费强。记录谁付了、为什么付。

07

公开发布

发布是一次活动，推广是长期并行

关键点

软发布 → 修致命问题 → 再公开推。部署、支付、邮件、分析、客服、备份、隐私政策，一个都不能少。

✓ 做到位 → 四两拨千斤

  • 有非朋友来源的用户，说明渠道真的通了。
  • 支付、支持、数据链路全通，能持续迭代。
  • 发布只是开始，不是终点，节奏在你自己手里。
  • 有分析数据，知道用户从哪来、在哪掉。

✕ 没做到 → 后果严重

  • 大爆炸发布，等完美，结果错过窗口。
  • 发布后才发现支付没通、客服没人管、数据没埋点。
  • 用户来了一波，基础体验有洞，留不住。
  • 发布当天很热闹，第二天归零。
☠ 典型死法：一次性发布，无人接住
动手

做发布清单，逐项打勾：域名、支付、邮件、分析、客服、备份、隐私政策、帮助文档、更新日志。

08

增长 / 商业化

推广从第一天开始，不是发布后才想

关键点

内容、社区、SEO、合作、广告；定价实验。找到可重复的获客渠道，比一次性热点重要。每周固定时间做推广，记录每个渠道的转化。

✓ 做到位 → 四两拨千斤

  • 找到可重复的获客渠道，不再靠运气。
  • 有正现金流或可预期的现金流。
  • 不被单一渠道绑架，抗风险能力强。
  • 定价有实验、有依据，不是拍脑袋。

✕ 没做到 → 后果严重

  • 最后才想钱，定价靠猜。
  • 获客靠朋友和一次性热点，不可持续。
  • 免费用户一大堆，转化率极低，不知道怎么改。
  • 收入归零那天，才发现没有第二条路。
☠ 典型死法：最后才想钱
动手

每周固定 2 小时做推广，记录每个渠道的转化。公开构建，把过程发出去。

09

维护 / 迭代 / 退出

设好退出条件，不要舍不得

关键点

加码、转型、维持、关停。每季度回看动机和成功标准，做明确决策。关停不是失败，是把精力释放给下一个机会。

✓ 做到位 → 四两拨千斤

  • 及时止损，把精力放到下一个。
  • 持续迭代的项目有节奏，不疲劳。
  • 关停也是成功，因为你知道了什么不行。
  • 你手里的经验，变成下一个项目的起点。

✕ 没做到 → 后果严重

  • 舍不得关停，耗死自己。
  • 无限期维护，没有新鲜感，也没有增长。
  • 把「坚持」当美德，其实是路径依赖。
  • 机会成本巨大，错过下一个真正值得做的事。
☠ 典型死法：耗死
动手

每季度一次复盘，写下继续或关停的理由。回看 why.md 和 one-pager.md。

每个节点，设一道决策门

不通过，不往下走。独立开发者最缺的不是更多步骤，而是「不通过就不走」的纪律。

节点 通过条件 不通过怎么办
00 封存动机 能一句话说清为谁解决什么 不写代码，先想清楚
01 问题验证 有人现在为这个问题花时间 / 钱 缩小或换方向
02 赌注与边界 一页纸写清，且知道不做什么 砍功能，重新写
03 手工 / 原型 用户觉得核心流程有价值 回到 01 重新验证
04 MVP 陌生人能独立完成核心任务 修闭环，不加功能
05 朋友碰撞 拿到盲点和种子用户 换人聊，别只问朋友
06 私测 / 预售 有人付费、续费、推荐 调整定位或价格
07 公开发布 有非朋友来源的用户 检查渠道和落地
08 增长 / 商业化 获客可重复，现金流可预期 不加功能，改模式
09 维护 / 退出 明确继续投入或及时止损 关停，释放精力

不是瀑布，是一圈一圈的循环

作坊式开发的全生命周期，不是一条直线，而是一个循环。每个节点都可能回到上一个节点，也可能直接关停。

你不需要一次做对所有事，你只需要在关键节点上，不骗自己。

记录 → 验证 → 做 → 分享 → 收钱 → 放大 / 关停
